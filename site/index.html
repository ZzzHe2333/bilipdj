CORE FEATURES

不是单独的排队窗口，
而是一套统一的直播排队系统。

01

弹幕驱动排队

监听直播间消息并按规则加入队列，也支持管理员手动调整、删除与推进。

02

统一状态源

Server 作为唯一业务状态源，Windows、Web、OBS 与第三方客户端共用一套队列与权限。

03

OBS 实时展示

将队列和状态直接提供给直播画面展示层，减少主播在多个窗口之间重复维护。

04

权限与礼物规则

把管理员、用户权限与礼物相关规则集中在后端处理，前端只负责交互与展示。

05

Windows + Web

桌面客户端和 Web 控制台共享后端能力与 Aurora 主题配置，操作结果保持同步。

06

可扩展插件架构

平台获取逻辑可逐步通过插件扩展，让新的直播平台接入不再绑死主程序。

ARCHITECTURE

前端只负责交互，业务规则只保留一份。

BiliPDJ 的核心原则是：队列、权限、平台连接、主题与存档由 Server 统一管理。这样从 Windows 切到 Web，或把状态展示到 OBS 时，不需要再同步另一套业务数据。

GET STARTED · 3 STEPS

从下载到 OBS，三步开播。

所有操作在本机进行，无需部署公网服务器。先运行程序并连接直播间，再添加 OBS 浏览器源。

01

下载并解压

Windows 主播使用 Tk 便携版，解压后启动 main.exe；更习惯浏览器管理的用户选择 Web Portable，启动 BiliPDJ-Web.exe。

02

填写直播间号

打开“设置 → 平台参数”，填写 B 站直播间号或抖音 Live ID，保存并启动服务；可在“激活平台”选择要监听的平台。

03

OBS 添加浏览器源

OBS → 来源 → 浏览器，粘贴下方本地地址。推荐从 800 × 600 开始设置宽高，再根据直播布局调整。

FAQ

常见问题。

OBS 背景如何透明？

使用 http://127.0.0.1:9816/index 作为 OBS 浏览器源，不要添加为普通屏幕捕获；展示层可配置文字、描边和背景样式。实际透明效果取决于队列展示样式。

数据和配置存在哪里？

默认保存在本机的程序运行数据目录，包含队列存档、配置与日志。备份文件与源程序分开管理；升级之前建议保留原有运行目录。

为什么不能把管理端口直接暴露公网？

本地管理接口用于受信任环境，配置可能含 Cookie 或其他凭据。路由器端口映射并不等于完成身份认证；远程访问应通过 VPN 或额外具备认证与访问控制的网关。

两个发行包都需要下载吗？

不需要。普通 Windows 使用 Tk 便携版；偏好浏览器控制台选择 Web Portable。两种客户端遵循同一套 Server 业务状态设计。

安全提示

Cookie、SESSDATA、bili_jct 等登录凭据不应上传到公开仓库或暴露到公网。默认本地管理服务不应直接作为公网服务使用。
